Education OS From a personal learning problem to a live multi-tenant education platform.

Education OS is a live, multi-tenant education platform focused on music schools. It brings learning materials, assignments, feedback, and live teaching into one protected environment while allowing each institution to retain its own curriculum, workflows, branding, and permissions.

06 Core User Journeys

Three foundational workflows across every tenant workspace.

Access Architecture

Invitation, onboarding and access

A learner enters through a tenant-specific invitation. Authentication confirms identity, while membership and approval determine whether the learner can enter that school's workspace.

The product handles pending membership, approval, missing membership and direct-link return as explicit states rather than treating them as generic errors.

STATE 01 Learner enters through a tenant-specific invitation link
STATE 02 Authentication confirms identity (distinct from school membership)
STATE 03 Pending or missing membership handled as explicit UI states
STATE 04 Educator approval unlocks workspace and preserves direct-link return
Persistence Decision

Homework and feedback

The key product decision is persistence. Homework is not treated as a temporary message exchange. Assignment state remains visible, submissions stay connected to the relevant work and feedback can be revisited as part of the learner's history.

Private files are resolved only for authorised users and delivered through short-lived signed access rather than public file URLs.

STEP 01 Educator assigns work → learner receives structured instructions
STEP 02 Learner submits private practice recording or training video
STEP 03 Coach is notified and reviews private media via short-lived signed access
STEP 04 Learner receives persistent feedback connected to their learning history
Real-Time Classroom

Live teaching

Learner opens the tenant classroom → access is validated → learner joins the live session → teaching continues inside the wider learning workflow.

For music teaching, the product has explored separating the normal microphone channel from accompaniment audio so conversation and music can be controlled independently.

LIVE 02 Tenant membership and live classroom permissions are validated
LIVE 03 Learner joins Daily.co session (independent mic + accompaniment audio exploration)

07 AI-Assisted Design & Development

Extending design practice into working software

Education OS became an experiment in how far I could extend my practice as a product designer using AI-assisted development. My working loop became:

Define the workflow → implement it → exercise it in the browser → inspect unexpected behaviour → revise the product logic → test again

React and TypeScript provide the application layer. Supabase provides authentication, Postgres data, Row Level Security, SQL functions and private Storage. Daily.co powers live classes, while Bunny remains part of the media ecosystem.

AI accelerated implementation, but it did not remove the need for product judgement. Generated changes still needed to be reviewed against the intended user journey, tenant boundaries and existing data. A technically successful implementation could still represent the wrong product decision.

08 What Working Software Exposed

Implementation as design evidence

Moving beyond static screens surfaced product-design problems that are easy to miss in Figma:

Identity vs. Access Authentication and membership are separate states.
Authority Boundaries Platform administration and school-level educator authority require different permissions.
Context Switching Tenant switching changes permissions and available actions, not only navigation.
Protected Media Private media needs an access lifecycle rather than simply a file URL.
Deep Routing Direct links need to survive authentication.
Synchronisation Loading and synchronisation can become security as well as UX states.
Learning Memory Assignment and feedback history needs persistence rather than message-like ephemerality.
09 What Changed in My Design Practice

The boundary of what I can design moved.

The most important outcome of Education OS is not that I became a software engineer. Previously, much of my work ended at validated flows, interface systems, prototypes and developer handoff. With AI-assisted development I can carry product decisions further into implementation, test them against real application behaviour and use what happens in the working product as design evidence.
